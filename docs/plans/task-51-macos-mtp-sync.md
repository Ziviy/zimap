# Архитектурный и технический план: Задача #51 — Автоматизированная передача карт по протоколу MTP на macOS (CLI Sidecar «zimap-mtp»)

> **Статус**: План подготовлен к реализации  
> **Версия спецификации**: 1.0.0  
> **Целевая платформа**: macOS (Apple Silicon arm64 / Intel amd64)  
> **Связанные компоненты**: `cmd/zimap-mtp`, `internal/device`, `app_device.go`, `GarminDeviceView.jsx`, `i18n.js`  
> **Автор**: Lead Architect / Senior Software Engineer  

---

## 1. Контекст, проблема и пользовательские сценарии

### 1.1. Физическая и системная природа проблемы на macOS
* **Современные часы Garmin** (серии Fenix 5 Plus, Fenix 6, Fenix 7, Fenix 8, Epix 2, Enduro, Forerunner 255/265/955/965):
  * Не поддерживают режим USB Mass Storage (MSC / стандартный съемный накопитель). Этот режим был полностью удален производителем ввиду интеграции музыкальных сервисов (Spotify, Deezer) и DRM.
  * Имеют в настройках только два USB-режима:
    1. **MTP** (Media Transfer Protocol) — файловый протокол PTP/MTP;
    2. **Garmin** (Spanner/Serial) — служебный телеметрический протокол для NMEA и зарядки (не является накопителем ни на одной ОС).
* **Ограничение платформы macOS**:
  * В ядре Darwin и файловом менеджере Finder **полностью отсутствует нативный драйвер MTP**.
  * При подключении часов по кабелю в режиме MTP операционная система видит физическое USB-устройство (`IOUSBHostDevice` с Vendor ID `0x091E`), но **не монтирует том в `/Volumes/`**.
  * В результате на macOS пользователи вынуждены либо скачивать стороннюю программу OpenMTP и вручную перетаскивать файлы, либо использовать Windows / Android-эмуляторы.

### 1.2. Цель задачи
Реализовать бесшовную, автоматическую передачу скомпилированных карт `.img` прямо из интерфейса ZiMap во вкладке **«Устройство Garmin»** при подключении часов Garmin по USB-кабелю на macOS в режиме MTP, без необходимости открывать сторонние утилиты.

### 1.3. Пользовательские сценарии (User Stories)
1. **Сценарий 1 (Автоматическое обнаружение часов в MTP-режиме)**:
   Пользователь подключает часы Garmin к Mac через USB-кабель. ZiMap автоматически обнаруживает устройство, считывает его имя (например, *Garmin fenix 7 Sapphire Solar*), объем хранилища (всего / свободно) и список уже установленных карт в папке `GARMIN/`.
2. **Сценарий 2 (Проверка актуальности и передача в 1 клик)**:
   Приложение сравнивает карты на часах с локальными сборками из «Мои карты» и активирует кнопку **«Загрузить на Garmin»** / **«Обновить на устройстве»**.
3. **Сценарий 3 (Потоковый прогресс и отмена)**:
   Во время передачи в реальном времени отображаются переданные мегабайты, скорость (МБ/с), процент выполнения и оставшееся время (ETA). При нажатии кнопки «Отмена» передача мгновенно и безопасно прерывается.
4. **Сценарий 4 (Интеллектуальная обработка конфликтов USB)**:
   Если на Mac запущен `Garmin Express` или `Android File Transfer`, монопольно захватывающий порт USB, ZiMap показывает информативную подсказку с предложением закрыть конфликтующее приложение.

## 2. Анализ архитектурных альтернатив и выбор решения

| Критерий | Вариант 1: Standalone CLI-сайдкар `zimap-mtp` | Вариант 2: Монолитное CGO-встраивание в `zimap` | Вариант 3: FUSE / сторонние kext |
| :--- | :--- | :--- | :--- |
| **Изоляция сбоев** | 🟢 **100%**: паника в USB-драйвере не роняет GUI-приложение | 🔴 **0%**: любой SIGSEGV в C-коде роняет процесс Wails | 🔴 Требует отключения SIP / Recovery |
| **Кросс-компиляция** | 🟢 Основной бинарник собирается стандартно без CGO | 🔴 Сложная сборка с mingw/libusb для Windows | 🔴 Неприменимо для обычных пользователей |
| **Размер и зависимости** | 🟢 Вспомогательный бинарник ~8-12 МБ в `Contents/Helpers/` | 🟡 Увеличивает размер основного бинарника | 🔴 Зависимость от macFUSE |
| **Тестируемость** | 🟢 CLI тестируется независимо в терминале через mock/stdin/stdout | 🟡 Сложное мокирование C-интерфейсов | 🔴 Практически не тестируется |

**Выбор**: **Вариант 1 (CLI-сайдкар `zimap-mtp`)**.  
Библиотека [`ganeshrvel/go-mtpx`](https://github.com/ganeshrvel/go-mtpx) (на которой базируется популярнейший OpenMTP) уже решила все низкоуровневые проблемы взаимодействия с MTP-устройствами на macOS (таймауты пакетов, буферы чтения, обработка Garmin-дескрипторов). Вынос этой логики в отдельный бинарник `zimap-mtp` гарантирует 100% стабильность основного интерфейса ZiMap.

### 3.1. Подпроект CLI-сайдкара (`cmd/zimap-mtp`)

Создается отдельная точка входа `cmd/zimap-mtp/main.go`, компилируемая в исполняемый файл `zimap-mtp`.

#### Протокол команд CLI:
1. **Обнаружение устройства**:
   ```bash
   zimap-mtp detect
   ```
   *Вывод в stdout (JSON)*:
   ```json
   {
     "success": true,
     "device": {
       "connected": true,
       "vendorId": "091e",
       "productId": "4c43",
       "friendlyName": "fenix 7 Sapphire Solar",
       "manufacturer": "Garmin",
       "model": "fenix 7",
       "serialNumber": "3412345678",
       "batteryLevel": 88,
       "storage": {
         "storageId": 65537,
         "description": "Primary",
         "totalBytes": 32212254720,
         "freeBytes": 14285714285,
         "maxObjectSize": 4294967295
       }
     }
   }
   ```

2. **Получение списка пользовательских карт**:
   ```bash
   zimap-mtp list-maps --storage-id=65537
   ```
   *Вывод в stdout (JSON)*:
   ```json
   {
     "success": true,
     "maps": [
       {
         "objectId": 1042,
         "fileName": "russia-northwestern.img",
         "internalTitle": "OSM Russia Northwestern",
         "size": 734003200,
         "modified": "2026-10-12T14:30:00Z"
       }
     ]
   }
   ```

3. **Загрузка карты на устройство**:
   ```bash
   zimap-mtp upload --storage-id=65537 --source="/path/to/local/map.img" --target-dir="GARMIN"
   ```
   *Потоковый вывод в stdout (Newline Delimited JSON)*:
   ```json
   {"event": "start", "totalBytes": 734003200}
   {"event": "progress", "sentBytes": 36700160, "totalBytes": 734003200, "percent": 5, "speedBps": 10485760, "etaSeconds": 66}
   {"event": "progress", "sentBytes": 73400320, "totalBytes": 734003200, "percent": 10, "speedBps": 11010048, "etaSeconds": 60}
   {"event": "done", "objectId": 1043, "totalBytes": 734003200, "elapsedSeconds": 68.4}
   ```

4. **Удаление карты**:
   ```bash
   zimap-mtp delete --storage-id=65537 --object-id=1042
   ```

5. **Проверка конфликтов портов USB**:
   ```bash
   zimap-mtp check-conflicts
   ```
   *Возвращает список запущенных приложений (`Garmin Express`, `Android File Transfer`, `OpenMTP`), блокирующих USB-интерфейс.*

## 4. Пошаговый план реализации

### Фаза 1: Разработка ядра CLI-сайдкара `cmd/zimap-mtp`
- [ ] Инициализировать пакет `cmd/zimap-mtp` с поддержкой `github.com/ganeshrvel/go-mtpx`.
- [ ] Реализовать команду `detect`: открытие MTP-сессии, считывание дескрипторов Garmin, получение Primary Storage.
- [ ] Реализовать команду `list-maps`: навигация по каталогу `GARMIN/`, парсинг `.img` заголовков (offset 0x49) через буферизованный диапазон MTP для извлечения `InternalTitle`.
- [ ] Реализовать команду `upload`: передача файла по MTP с вычислением плавающей скорости, отправкой событий прогресса в stdout и поддержкой graceful shutdown (очистка временного объекта при `SIGINT`).
- [ ] Реализовать команду `delete`: удаление карты по `objectId` с проверкой защиты системных карт.

### Фаза 2: Менеджер сайдкара в бэкенде ZiMap (`internal/device/mtp_*.go`)
- [ ] Создать `internal/device/mtp_service.go`:
  - Поиск бинарника `zimap-mtp` (в `tools/mtp/` при разработке или в `ZiMap.app/Contents/MacOS/` в релизном бандле).
  - Обертка вызова команд через `exec.CommandContext` с парсингом JSON-потока.
  - Детектирование конфликтов с процессами `Garmin Express`.
- [ ] Создать `internal/device/mtp_detector.go`:
  - Интеграция с общим циклом сканирования `ScanGarminDevices()`: если в `/Volumes/` нет накопителя, но подключены часы MTP, возвращать синтезированное устройство `GarminDevice` с флагом `IsMTP: true`.

### Фаза 3: Интеграция в Wails IPC (`app_device.go`)
- [ ] Маршрутизация операций синхронизации:
  - В методах `SyncMapToDevice` и `SyncAllOutdatedMaps` проверять флаг `device.IsMTP`.
  - При `IsMTP == true` вызывать `mtpService.UploadMap()`, транслируя события прогресса в существующую шину `device:sync_progress`.
  - В методе `CancelDeviceSync` вызывать отмену контекста сабпроцесса `zimap-mtp`.
- [ ] В методе `DeleteDeviceMap` направлять удаление через MTP для соответствующих устройств.

### Фаза 4: Адаптация пользовательского интерфейса (`GarminDeviceView.jsx` и `i18n.js`)
- [ ] Обновить карточку устройства в `GarminDeviceView.jsx`:
  - При обнаружении MTP-часов отображать бейдж `MTP` рядом со статусом «Подключено».
  - Скрыть предупреждение о необходимости сторонних программ, активировав нативные кнопки «Загрузить на Garmin» и «Синхронизировать всё».
  - Добавить баннер конфликта, если обнаружен запущенный `Garmin Express` («Закройте Garmin Express для продолжения»).
- [ ] Добавить необходимые ключи локализации (RU/EN) в `frontend/src/i18n.js` и проверить паритет через `npm test`.

### Фаза 5: Скрипты сборки и упаковка бандла
- [ ] Добавить в Makefile / build scripts сборку универсального бинарника `zimap-mtp` (`lipo -create -output zimap-mtp zimap-mtp-arm64 zimap-mtp-amd64`).
- [ ] Настроить автоматическое копирование `zimap-mtp` внутрь бандла `ZiMap.app/Contents/MacOS/` при выполнении команды `wails build`.
- [ ] Покрыть интеграцию тестами `mtp_service_test.go` с моком потока stdout.

## 5. Оценка трудоемкости и рисков

* **Оценка времени**: ~8-12 рабочих часов.
* **Основные риски**:
  1. *Конфликт монопольного доступа к USB*: Решается автоматическим обнаружением фонового процесса `Garmin Express` и понятным алертом пользователю.
  2. *Нестабильность USB-кабелей*: Решается таймаутами пакетов и очисткой неполных объектов на часах в `defer` при ошибке.
